# 사라진 도시 — 담은 톨레도가 상세 일정에 없던 일

## 증상

3단계에서 톨레도를 담고(3곳, 0.6일), 4단계 경로에도 **톨레도가 있는데**
(마드리드 → 톨레도 → 세고비아 → …), 그 아래 상세 일정에는 톨레도가 한 곳도
나오지 않았다. 2일차는 세고비아 당일치기였다.

## 원인 — 셋이고, 셋 다 '조용히' 가 문제였다

### 1. 날을 나누는 쪽이 첫날이 짧다는 것을 몰랐다

날을 나누는 `packDays` 와 하루 일정을 짜는 `buildDay` 는 서로 다른 것을
알고 있었다.

| | 첫날을 아는가 | 하는 일 |
|---|---|---|
| `packDays` | **모름** — 하루는 567분 | 무엇을 며칠에 나눌지 |
| `buildDay` | 앎 — 18시 착륙이면 20:05부터 | 그날 몇 시에 무엇을 |

그래서 `packDays` 는 첫날에 '마드리드 294분 + 톨레도 133분' 을 얹었고,
`buildDay` 는 20:05부터 두 시간뿐이라 마드리드 두 곳만 넣고 톨레도 몫을
**말없이 버렸다**. 경로에는 남고 일정에서만 사라진 것이 이 때문이다.

### 2. 근교를 남은 자투리에 밀어 넣었다

톨레도는 왕복 140분에 담은 볼거리가 384분이다. 하루(567분)를 통째로 주면
524분으로 다 볼 수 있다. 그런데 마드리드를 294분 보고 남은 273분에 밀어
넣어 133분만 배정했다. 왕복 두 시간 이십 분을 쓰고 담은 것의 3분의 1을
본다는 뜻이고, 나머지 251분은 '같은 근교는 하루만' 규칙에 걸려 버려졌다.

### 3. 남는 날이 앞 날을 통째로 베꼈다

여유 날을 만들 때 앞 날을 복사하고 구간만 비웠다. 앞 날이 근교 당일치기면
`city`·`isDayTrip`·`dayTripMode` 까지 따라와서, 남는 날이 **가는 길도 없는
두 번째 세고비아 당일치기**가 되었다. 톨레도는 하루도 못 받았는데
세고비아는 두 번 간 것이다.

## 고친 방법

**1. 첫날 예산을 날 나누는 쪽에도 준다.** `packDays(…, firstDayMin)`.
착륙 시각 + 입국심사·시내 이동·짐 풀기가 끝나는 시각부터 그날 마감까지가
첫날 예산이다. 3단계(`Step3Course`)도 같은 값을 넘긴다 — 두 화면이 다른
가정으로 세면 또 어긋난다.

**2. 자를 거면 자를 이유가 있어야 한다.**

```
빈 날이면            → 간다. 다 못 봐도 그게 오늘의 최선이고, 남는 몫은 unseen 으로 알린다.
이미 다른 도시를 본 날 → 담은 것을 오늘 다 볼 수 있을 때만 얹는다.
```

톨레도는 둘째 규칙에 걸려 첫날에 얹히지 않고, 빈 날을 하나 받아 384분을
다 본다. '빈 날이면 간다' 를 빼면 안 된다 — 사용자가 손수 '짐 안 옮기기'
로 바꾼 왕복 6시간 50분짜리 세비야는 하루를 다 써도 왕복을 못 이기는데,
그때 안 간다고 하면 가겠다고 한 도시가 통째로 사라진다. 잘라 가는 것보다
나쁘다.

**3. 남는 날은 그 도시에서 쉬는 날로 만든다.** 앞 날을 베끼지 않고,
짐을 둔 도시(`sleepAt`)에서 쉬는 날을 새로 만든다.

**4. 못 본 몫을 화면에 말한다.** `unseen` 은 예전에도 계산했지만 화면에
쓰이지 않았다. 이제 4단계에 "당일치기로는 여기까지입니다 — 세고비아 2.3시간
남음, 여기서 자기" 로 뜬다. 눌러 거점으로 바꿀 수 있다.

## 결과

|  | 고치기 전 | 고친 뒤 |
|---|---|---|
| 1일차 | 마드리드 294 + 톨레도 133 (실제로는 마드리드 두 곳만) | 마드리드 115 (18시 착륙에 맞는 몫) |
| 2일차 | 세고비아 279 | 마드리드 179 |
| 3일차 | *세고비아 0분* (가지 않는 두 번째 세고비아) | **톨레도 384 — 담은 것 전부** |
| 4일차 | 세비야 | 세고비아 279 |
| 톨레도 | 251분 버림, 상세 일정에 없음 | 버린 것 없음 |

## 다시 안 나게 한 방법

`scripts/planner-check.mjs` 에 **약속**을 검사하는 절을 넣었다. 결과가
아니라 약속이다 — 담은 도시는 상세 일정에 나오거나, 안 나오는 이유가 화면에
말할 수 있는 형태로 남아 있어야 한다(날이 모자람 `overflow`, 당일치기로는
거기까지 `unseen`). **조용히 없어지는 것만 실패다.**

252가지 조합(7개 도시묶음 × 4가지 일수 × 3가지 도착시각 × 3가지 담은 양)에
세 가지를 건다.

1. 말없이 사라지는 도시가 없다
2. 하루를 통째로 주면 다 볼 근교를 잘라 가지 않는다
3. 안 가는 근교 날이 없다

저녁 도착(20:05)을 함께 돌린다 — 그게 방아쇠였다. 세 가지 고침을 하나씩
되돌려, 각각 **다른 검사가** 잡는 것을 확인했다.

| 되돌린 것 | 걸린 검사 | 나온 말 |
|---|---|---|
| 첫날 예산 | 말없이 사라지는 도시 | 16가지 조합에서 사라짐 |
| 근교 자투리 | 하루면 다 볼 근교 | 44가지 — 톨레도 128분 남김 (왕복 140+볼거리 246 ≤ 하루 504) |
| 남는 날 베끼기 | 안 가는 근교 날 | 598일 |
