# 안드로이드에서 쓸 수 있는가

## 보고된 것

"안드로이드에서 날짜 선택이 안 된다."

## 원인 — 두 날짜 칸이 서로를 묶고 있었다

```jsx
<input type="date" value={startDate} max={endDate} />   // 첫날
<input type="date" value={endDate}   min={startDate} /> // 마지막 날
```

첫날은 마지막 날보다 뒤로 못 가고, 마지막 날은 첫날보다 앞으로 못 간다.
그래서 여행을 다른 달로 옮기려면 **반드시 '마지막 날 → 첫날' 순서로만**
가능하다. 그 순서를 알 길이 없다.

안드로이드 크롬의 달력은 범위 밖 날짜를 **회색으로 막아 탭이 아예 안
먹는다.** 데스크톱은 키보드로 타이핑해 넘어갈 수 있어 보이지 않았다.

실제 재현(Pixel 7 에뮬레이션):

```
첫날     max="2026-10-07"
마지막날 min="2026-10-01"

첫날에 2026-11-01 입력 → 브라우저 판정 "무효 (max 초과)"
안드로이드 달력이 막는가: 예
```

### 고친 방법

제약을 없애고, 순서가 뒤집히면 **기간을 유지한 채 반대쪽을 같이 옮긴다.**
항공권 사이트들이 하는 방식이라 놀랄 일이 없다.

- 첫날을 마지막 날보다 뒤로 → 마지막 날이 따라온다
- 마지막 날을 첫날보다 앞으로 → 첫날이 따라온다

## 왜 검증이 못 잡았나

검증 스크립트가 input 의 `.value` 를 **프로그래밍으로 직접 넣고 있었다.**

```js
const setValue = (el, v) => {
  const s = Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, 'value').set;
  s.call(el, v); ...
};
```

이것은 `min`/`max` 검증을 통째로 우회한다. 그래서 100건이 넘는 검사를
통과하면서도 정작 사용자가 못 쓰는 상태였다. 새 검사는 브라우저의
`validity` 를 직접 확인한다.

## 함께 찾은 것

같은 검사에서 두 가지가 더 나왔다. 둘 다 지난번 작업에서 들어간 것이다.

### 시각 칸이 24px 였다

공통 입력 스타일 규칙에 `input[type='time']` 이 빠져 있었다.

```css
input[type='text'], input[type='date'], input[type='number'], select { ... }
                                     ↑ time 이 없다
```

착륙·이륙 시각 칸만 스타일이 안 먹어 **높이 24px 짜리 맨몸 입력**으로
나왔다. 손가락으로 누르기 어렵고, 옆의 날짜 칸(46px)과 나란히 있어 눈에도
잘 안 띈다.

### 320px 화면에서 가로로 100px 삐져나갔다

`.date-pair` 가 `grid-template-columns: 1fr 1fr` 인데, 그리드 칸은 기본이
`min-width: auto` 라 자식이 줄어들지 못한다. 날짜·시각 입력은 브라우저가
정한 고유 최소 너비가 커서 갤럭시 S9+(320px)에서 넘쳤다.

`min-width: 0` 을 풀어 주고, 360px 이하에서는 위아래로 쌓는다.

### 단계 표시가 6px 이었다

머리줄의 단계 막대는 앞 단계로 돌아가는 **버튼**이기도 한데 높이가 6px
이었다. 보이는 막대는 그대로 두고 위아래 여백으로 36px 를 확보했다.

## 검증

`app/scripts/android-check.mjs` — Pixel 7(412px)과 Galaxy S9+(320px)
두 기기 조건으로 돌린다.

- 두 날짜 칸이 서로를 막지 않는가 (`min`/`max` 가 비어 있는가)
- 첫날·마지막 날을 마음대로 옮길 수 있고 반대쪽이 따라오는가
- 시각 칸이 보이는가
- 가로로 삐져나가지 않는가
- 누를 것이 36px 이상인가
- 탭으로 도시를 고르고 2단계까지 가는가
- 단계 표시를 눌러 앞 단계로 돌아가는가

### 이 검증의 한계

안드로이드 크롬과 **같은 엔진(Chromium)** 에 **같은 기기 조건**(터치·좁은
화면·모바일 UA)을 씌운 것이지 실기기가 아니다. 레이아웃·터치·입력 검증에는
충분하지만 이런 것은 잡지 못한다.

- 삼성 인터넷, 파이어폭스 등 다른 브라우저의 고유 동작
- 기기 제조사가 바꾼 달력·키보드 UI
- 실제 기기의 성능·메모리 한계
