# 요구사항 정의서 — 여행 계획 앱

이 문서 하나로 지금의 앱을 **같은 결과물로** 다시 만들 수 있는 것을 목표로
한다. 화면과 흐름뿐 아니라, 사용자와 합의해 정한 **판단 기준과 수치**까지
적는다. 그 수치가 곧 이 앱의 성격이기 때문이다.

- 살아 있는 구현: `app/` · 데이터 파이프라인: `pipeline/`
- 배경과 결정 이유는 `docs/01` ~ `docs/16` 에 나뉘어 있다. 이 문서는 그
  결론만 모은 것이다.

---

## 1. 무엇을 하는 물건인가

스페인을 모르는 사람이 **모바일에서 30분 안에** 실제로 쓸 수 있는 여행
일정을 만든다. 결과물은 날짜별 시간표, 도시 간 이동 수단과 시간, 숙박지,
지도, 그리고 내려받을 수 있는 파일이다.

### 원칙

1. **고르라고 하지 말고 제안한다.** 2,000개 목록에서 고르라는 것은 고를 수
   없다는 뜻이다. "이 도시는 보통 이렇게 돕니다" 를 먼저 주고 거기서 빼고
   더한다.
2. **추측한 값은 추측이라고 적는다.** 실제 시간표에서 온 값과 추정치를
   화면에서 구별한다.
3. **확인하지 못한 정보는 넣지 않는다.** 좌표를 확인 못 한 장소는 넣느니
   빠뜨린다.
4. **되돌릴 수 있어야 한다.** 어느 단계에서든 앞으로 돌아가 고칠 수 있고,
   고친 것이 뒤에 반영된다.
5. **막힌 이유는 화면에 있어야 한다.** 잠긴 버튼만 두지 않는다.

### 하지 않는 것

예약·결제, 로그인·계정, 서버(전부 정적 파일 + 브라우저 저장), 실시간 요금
조회, 스페인 외 국가.

## 3. 데이터

### 규모

도시 60곳 · 권역 6 · 섬 3 · 장소 2,142개.

### 출처와 라이선스

- Wikivoyage (CC BY-SA 4.0) — 장소 목록과 설명
- Wikidata (CC0) — 좌표, 식별자
- OpenStreetMap contributors (ODbL) — 좌표 보완
- Wikimedia Commons — 사진. **저작자와 라이선스를 화면에 표기해야 한다**
- Renfe 공개 데이터(GTFS) — 실제 열차 시간표

출처 표기는 앱 하단에 항상 보인다.

### 도시(City)

```
slug, name, nameEn, region, macroRegion, lat, lon,
tagline        한 줄 소개
suitedFor      "이런 분께"
highlights[]   대표 명소 이름
themes{}       테마별 장소 수
profile{}      테마별 성격 점수 0~3 (취향 역산에 쓴다)
nights[]       [최소, 권장] 숙박일
isHub          지역 거점인가 (거점 판정의 입력)
firstTimer     처음 가는 사람에게 권할 만한가
island         섬 id (있으면)
photo, photoCredit{author, license, source}
season{best, note}
itemCount
```

### 장소(Item)

```
id, city, name, nameLocal, nameEn, theme, lat, lon,
summary        한 줄
why            왜 가는가 (순위 계산의 입력)
practical      실무 정보(영업시간·예약 등)
caution        주의점
durationMin    머무는 시간
priceEur       요금 (null = 미상)
popularity     1~5
energy         1~5 체력
indoor         실내인가
bestSlots[]    morning / lunch / afternoon / dinner / night
district, tags[], photo
```

### 테마 8종

역사·유적 `history` / 예술·박물관 `art` / 랜드마크·건축 `landmark` /
자연경관 `nature` / 미식 `food` / 나이트라이프 `nightlife` /
액티비티 `activity` / 쇼핑·시장 `shopping`

### 섬

섬은 자치주가 아니라 **섬 하나가 여행 단위**다.

```
id, name, nameEn, region, cities[], rail(섬 안 철도 유무), note
```

- 1단계에서 섬은 **카드 한 장**으로 보인다(도시별로 나열하지 않는다).
- 고르면 그 섬의 거점 도시가 선택되고, **표시 이름은 섬 이름**이 된다
  (`slug` 는 거점 도시 그대로 — 저장된 계획이 깨지지 않아야 한다).
- 고르지 않은 섬 도시의 장소는 **가장 가까운 고른 도시로 옮겨 붙이고**,
  "🚗 소예르 방면" 처럼 어디쯤인지 표시한다.
- 섬 사이(테네리페↔그란카나리아)는 바다다. 철도가 없는 섬에 열차를 지어내지
  않는다. 150km 미만 해협은 페리를 쓴다.

## 4. 화면 흐름 — 5단계

### 1단계 · 기초 정보

**입력**

| 칸 | 규칙 |
| --- | --- |
| 스페인 첫날 / 마지막 날 | 서로 `min`/`max` 로 **막지 않는다**. 순서가 뒤집히면 기간을 유지한 채 반대쪽을 같이 옮긴다 |
| 현지 착륙 시각 / 현지 이륙 시각 | 공항을 고르기 전에도 **항상 보인다** |
| 입국 공항 / 출국 공항 | 26곳. 왕복이면 같은 곳 |
| 인원 | |
| 도시 선택 | 권역별 접이식. 한 번에 한 권역만 펴진다 |

**날짜·시각 이름 규칙 (중요)**
"출발일" 은 첫날, "출발 시각" 은 마지막 날을 뜻해 정반대 날을 가리켰다.
전부 **스페인 기준**으로 통일한다 — `스페인 첫날 / 스페인 마지막 날 /
현지 착륙 시각 / 현지 이륙 시각`. 귀국편은 다음 날 한국에 내리므로
"한국 도착일이 아니라 스페인을 떠나는 날" 이라고 명시한다.

**도시 카드**: 사진, 이름, `처음이라면` 배지, 한 줄 소개, 강점 테마 3개,
`자세히`(이런 분께 · 대표 명소 · 가기 좋은 때 · 사진 저작자).

**미리보기**: 도시를 하나라도 고르면 "이렇게 돌게 됩니다" — 숙박지 순서,
당일치기 표시, 도시 간 이동 시간. 4단계와 **같은 엔진**을 써야 한다.
미리보기가 실제와 다르면 오해를 만드는 화면이다.

### 2단계 · 취향

고른 도시에서 취향을 **역산해서 미리 채운다**. 사용자는 고치기만 하면 된다.

- 테마 8종 0~3
- 속도(1~5), 예산(low/mid/high), 하루 시작(early/normal/late)
- 나이트라이프, 숨은 곳 선호(discovery), 걷기 감내, 동행(couple/family/
  parents/friends/solo), 음식 취향 태그, 이동 제약, 사진, 교통 수단,
  근교 나들이 성향

**역산 규칙**: 고른 도시들의 `profile` 평균을 0~3 으로 정규화하되,
**평균이 0.25 미만인 테마만 0** 으로 둔다. 최저 테마를 기계적으로 0 으로
깎으면 바르셀로나 단독 선택에서 역사가 0 이 되는 식의 거짓이 나온다.

### 3단계 · 코스

도시마다 접이식 패널. 안에 들어가는 것:

1. **꼭 가야 하는 곳** (must-see)
2. **코스 카드 3장** — 꽉찬 / 보통 / 찍먹. 각각 담기는 곳 수와 예상 일수,
   근거 한 줄, 대표 사진
3. **일수 조절기** — 0.5일(반나절) 단위. "반나절 / 1일 / 1일 반"
4. **묶음 제안** — 함께 봐야 뜻이 통하는 것들(구엘 패키지 등). 통합권이
   있으면 낱장 합계와 나란히. `묶음 담기` / `묶음 빼기`
5. **미식 후보** — 접힌 상자에 따로. 일정과 동선에 영향을 주지 않는다
6. **장소 목록** — 점수순 **한 줄로 통합**. 테마는 줄마다 구분자(`🗼 랜드마크·건축`)
   로 표시한다. 테마별 접이식으로 나누지 않는다

**일괄 적용**: 도시가 둘 이상이면 `모든 도시에 한 번에 · 찍먹 / 보통 / 꽉찬`.
누른 뒤 도시별로 다시 고를 수 있다.

**도시 빼기**: 3단계에서 도시를 통째로 뺄 수 있다.

**다음 단계 조건**: `담은 곳 ≥ 일수 × 2` 같은 양 조건을 **걸지 않는다**.
분량은 사용자가 정한다. 막는 경우는 하나뿐 — **들르기로 한 도시인데 담은
것이 하나도 없는 경우.** 애초에 후보가 없는 도시는 조건에서 뺀다(사람이
담을 방법이 없으니 영영 안 풀리는 잠금이 된다). 막혔으면 **이유를 화면에
적는다.**

### 4단계 · 계획 3안

같은 우선순위로 하루 밀도만 다르게 짠 3가지를 탭으로 비교한다.

- **여정 바** — 도시 순서, `여기서 자기` ↔ `당일치기` 전환, 순서 바꾸기,
  **도시 빼기**(마지막 한 도시는 못 뺀다). 두 말의 뜻을 화면에 적어 둔다:
  - *여기서 자기* — 짐을 이 도시로 옮기고 밤을 보낸다. 옮기는 데 반나절이 든다
  - *당일치기* — 짐은 거점에 둔 채 아침에 나갔다 저녁 전에 돌아온다
- **날짜별 시간표** — 시각, 장소, 소요, **장소별 이동 수단**, 팁
- 줄마다 `✕`(빼기)와 `↑ ↓`(순서). ✕ 는 순서 바꾸기와 다른 묶음에 둔다
- **대안 제시** — 그 자리에 넣을 만한 다른 곳
- **렌터카 패널** — 빌리는 곳/반납하는 곳, 편도 반납료 범위, 세워 두는 날
  주차비, 대안 교통편과 시간·비용 차이, 고르면 일정이 어떻게 바뀌는지
- **숙박 제안** — 거점 도시별 숙소 유형과 지역
- 날이 모자라면 무엇이 밀려났는지, 남으면 남는다고 알린다

### 5단계 · 가이드

날짜별 최종 일정, 지도, 내려받기(계획 JSON, 지도 KML — 전체/경로만),
출처 표기.

## 5. 엔진 — 합의된 판단 기준

여기 있는 수치는 사용자와 논의해 정한 것이다. **바꾸면 앱의 성격이 바뀐다.**

### 5.1 거점 판정 (어디서 잘 것인가)

여러 도시를 고르면 전부에서 자는 것이 아니라, **거점을 정하고 나머지는
당일치기로 붙인다.** 거점 점수는 가중평균이다.

| 요소 | 가중치 | 뜻 |
| --- | --- | --- |
| `reach` | 0.30 | 근교를 여럿 품는가. 거점의 존재 이유 |
| `evening` | 0.25 | 저녁·밤에 할 것이 있는가 |
| `lodging` | 0.20 | 며칠 묵을 만한 곳인가 |
| `onward` | 0.15 | 다음 목적지로 나가기 쉬운가 |
| `volume` | 0.10 | 그 도시 자체의 볼 것 분량 |

- **당일치기 한계: 편도 120분(왕복 4시간).** 하루 활동 8시간 중 절반이
  이동이면 거기서 자는 편이 낫다.
- 저녁은 거점에서 보낸다.
- 당일치기 교통수단에서 **렌터카는 뺀다.** 근교 하루를 위해 차를 빌리지는
  않는다. 정기편이 없는 구간에서만 차가 남는다.
- **옮길 값어치**: 짐을 옮기려면 최소 1.5일치, 거점 근처면 2.5일치가
  있어야 한다.
- 순서는 **거점만** 대상으로 정한다. 당일치기 도시를 순서에 넣으면
  "세고비아 → 톨레도 렌터카 2시간 26분" 같은 유령 구간이 생긴다.
- 도시 수 ≤ 10 이면 Held-Karp 로 **정확한 최소 이동 순서**를 구한다.

### 5.2 장소 순위

일수와 무관하게 **모든 장소에 점수**를 매기고 순위표를 만든다.

| 요소 | 가중치 | 계산 |
| --- | --- | --- |
| 명성 `fame` | 0.40 | 위키 언어판 수 등 |
| 대표 지정 `must` | 0.30 | 도시 대표 명소로 지정되었는가 |
| 여행자 검증 `vetted` | 0.30 | 한국어 이름(0.4) + 가이드 문서(0.3) + 정보 있음(0.3) |

- `vetted` 는 **더하기만 한다.** 실무 정보가 없다고 감점하면 마요르 광장·
  에스파냐 광장 같은 무료 열린 공간이 통째로 밀린다(실제로 210곳 중 88곳이
  깎이고 알함브라가 60위로 떨어졌다).
- **그 일정이 있어야만 가는 곳 보정**: 경기가 있는 날에만, 예약제, 미사
  시간에만 — 이런 곳은 ×0.45. 이름이 아니라 사람이 적은 설명(`why`)에서
  판단한다(산 파우 '병원' 은 유네스코 건축이다).
- 틈새 항목 ×0.72. 도시 대표 명소는 이 보정에서 면제.
- **채택선 `RANK_FLOOR = 0.45`**

### 5.3 코스 등급

| 등급 | 분량 |
| --- | --- |
| 꽉찬 `full` | 순위대로 **최대 4일치** |
| 보통 `normal` | 상위권 **2일치** |
| 찍먹 `taste` | 최대 **3곳** |

도시마다 값어치가 다르므로 같은 등급이라도 담기는 양이 다르다. 그 도시에
그 등급이 없으면(반나절짜리 마을은 등급이 하나뿐) 가장 가까운 것을 쓴다.

### 5.4 하루 용량

```
하루 활동 시간 = {early: 9h, normal: 8h, late: 6.5h}[하루 시작]
                 × (0.78 + 속도 × 0.09)
장소 하나 = 머무는 시간 + 18분(옮기고 자리 잡는 시간)
```

### 5.5 미식 예외 (중요)

식사는 **일정을 늘리지 않는다.** 점심·저녁은 어차피 먹으므로 동선이 만드는
끼니 자리에 들어간다. 식당을 열 곳 담아도 소요 일수가 그대로여야 한다.

- 예전에는 미식이 소요 일수의 11~28%(세비야 28%)를 차지해 **숙박일과 거점
  판정까지 밀어 올렸다.** 식당 때문에 하룻밤이 더 잡히는 것은 계산 실수다.
- **간식은 다르다.** 오전·오후에도 갈 수 있다고 적힌 곳(츄러스 등)은 끼니가
  아니라 끼워 넣는 일정이라 시간을 실제로 쓴다.
- 남는 미식은 후보로만 남기고 동선에 넣지 않는다.

### 5.6 공항 시간

| 항목 | 값(분) |
| --- | --- |
| 입국 심사·수하물·세관 (한국에서 직항) | 55 |
| 유럽 경유로 들어옴 | 30 |
| 숙소에 짐 두고 나오기 | 30 |
| 장거리 국제선 체크인 권장 | 180 |
| 셍겐 안 단거리 | 120 |
| 공항 ↔ 시내 | `18 + 거리km × 1.5` (모르면 45) |

- 마지막 날 출국에는 **도시 간 이동 구간도 더한다.** 세비야에서 자고
  마드리드에서 뜨면 197분을 빼먹어 비행기를 놓친다.
- 착륙 시각이 늦으면 그날 가능한 일정을 줄이고, 이륙 시각이 이르면
  마지막 날을 비운다. **"마지막 날 오전/하루" 같은 선택은 두지 않는다** —
  시각이 있으면 계산으로 정해지고, 두 곳에서 같은 것을 정하면 어긋난다.

### 5.7 도시 간 교통

- **실제 시간표 우선**(Renfe GTFS). 없으면 회랑별 `분/km` 로 추정하고
  화면에 **추정이라고 표시**한다.
- 열차 / 버스 / 렌터카 / 항공 / 페리. 각각 소요·요금·환승을 제시하고
  기본값을 하나 고른다.
- 요일마다 운행이 다른 편이 있으므로 여행 시작 요일로 거른다.
- 바다를 건너면 육상 교통을 제시하지 않는다.

## 7. 견고성 요구사항

이 항목들은 실제로 사용자를 막았던 것들이다. **새로 만들어도 반드시 넣는다.**

1. **오류 경계(Error Boundary)** — 그리다 터져도 하얀 화면이 되면 안 된다.
   무엇이 잘못됐는지와 빠져나갈 길(다시 그리기 / 캐시 비우고 새로 받기 /
   백업 받기 / 처음부터)을 준다.
2. **서비스 워커 캐시에 배포 판 번호를 넣는다.** 이름이 고정이면 한 번
   받아 둔 데이터가 영원히 남아, 새 코드가 몇 주 전 데이터를 읽는다.
3. **새 판 알림** — 실행 중인 번들과 서버의 번들을 비교해 다르면 알린다.
   사파리는 탭을 되살리므로 '다시 열어도' 새로 받지 않는다. 사용자는 자기가
   예전 판을 쓰는지 알 길이 없다.
4. **데이터 받기 실패를 화면에 알리고 다시 받기를 준다.** 조용히 빈 목록이
   되면 안 된다.
5. **진단 정보** — 눌린 자리와 앱이 실제로 한 일을 짝지어 기록하고,
   브라우저·화면·실행 판·워커·캐시와 함께 복사/파일로 내보낸다.
   **기록은 페이지를 넘어 살아남아야 한다**(sessionStorage).
6. **날짜 입력에 서로를 가리키는 min/max 를 걸지 않는다.**
7. **모든 누를 것은 최소 36px.** 320px 화면에서 가로로 넘치지 않는다.
8. `html, body` 는 `height` 가 아니라 **`min-height: 100%`**.
9. 붙박이(sticky/fixed) 막대에 `backdrop-filter` 를 쓰지 않는다.

## 8. 검증 요구사항

새로 만들어도 이 수준의 자동 검증을 함께 만든다. **검증이 없으면 같은
물건이 아니다.**

| 스위트 | 무엇을 보는가 |
| --- | --- |
| `verify.mjs` | 전 기능 실사용. 눌러야 하는 것을 다 눌러 보고 값이 정말 바뀌는지 (현재 162검사) |
| `smoke.mjs` | 5단계 한 번 통과 |
| `edge.mjs` | 1일·1도시 / 14일·3도시 등 경계 |
| `android-check.mjs` | Pixel 7(412px)·Galaxy S9+(320px) — 날짜 제약, 넘침, 터치 크기 |
| `island-check.mjs` | 섬 식별, 바다 건너기, 묶음 |
| `rank-check.mjs` | 순위·등급·미식 예외 |
| `basing-check.mjs` | 거점 점수 내역 |
| `taste-check.mjs` | 취향 역산 (0 이 잘못 나오지 않는가) |
| `airport-check.mjs` | 공항 시간 |
| `routing-check.mjs` | 실제 시간표 대조 |
| `order-verify.mjs` | 최소 이동 순서 |

**엔진 두 개로 돌린다** — Chromium 과 WebKit(사파리). 아이패드에서만 나는
문제를 크로미움으로만 돌려서는 영영 못 본다.

**검증 작성 규칙**: `input.value` 를 코드로 직접 넣지 않는다. 그건 브라우저
검증을 통째로 우회한다 — 100건이 넘는 검사를 통과하면서 정작 사용자가 못
쓰는 상태였던 적이 있다. 브라우저의 `validity` 를 본다.

## 10. 해결된 문제 (기록)

**아이패드 사파리에서 특정 조작 후 화면이 비거나 눌리지 않던 문제 — 해결됨.**

원인은 `planner.ts` 의 **무한 루프**였다. 남는 날을 숙박지에 나눠 주는
자리에서 배부른 도시를 후보에서 빼지 않고 가중치만 낮춘 채 `continue` 했는데,
`continue` 는 남은 날을 줄이지 않는다. 메인 스레드가 통째로 막혀 화면이
그리다 만 채 멈추고 아무것도 눌리지 않았다. 자세한 것은 `18-the-hang.md`.

아래는 잡기까지의 기록이다. 새로 만들 때 같은 함정을 피하는 데 쓴다.

- 재현: 1단계 → 마드리드·중부 → 마드리드 선택 → 톨레도 누름
- 기기: iPad, Safari 26.6, 1600×1144, 다크 모드
- **재현되지 않는 곳**: 크로미움 전부, 헤드리스 WebKit(아이패드 크기·다크·
  터치 포함). DOM 은 완전하다 — 카드 8장, 사진 전부 로드, 좌표 정상, 오류 0
- **아닌 것으로 확인됨**: 낡은 캐시 / `height:100%` / 붙박이 막대의
  `backdrop-filter` / 계산 부하(가장 무거운 경우 6ms) / 데이터 크기(최대
  80KB) / 도시 사진·머리줄 고정·바닥 고정·그림자·1단계 미리보기를 전부 꺼도 재현
- **잡은 방법**: 화면이 죽으면 진단을 누를 수도 없으므로 계기부터 고쳤다 —
  멈춤 감시자(자바스크립트 막힘 / 그리기 막힘을 갈라 적는다), 페이지보다
  오래 사는 기록, 다시 열리면 앱이 먼저 말하기. 그러자 `자바스크립트가
  20.3초 멈췄습니다 (메인 스레드 막힘)` 와 `도시 7곳` 이 찍혔고, 그 둘이
  원인을 확정했다.
- **검사 요구사항 추가**: 엔진만 따로 돌려 시간 예산을 거는 검사가 필요하다
  (`planner-check.mjs`). 화면 검사로는 잡을 수 없다 — 브라우저가 멈추면
  검사도 함께 멈춘다.
- (예전 메모) 다음 단계: 앱에 넣어 둔 문제 찾기 스위치(`?off=...`)로 좁힌다.
  이번 판에서 `계획 미리 계산`·`아이템 받아오기` 축을 추가했고, 진단 기록이
  페이지를 넘어 살아남게 고쳤다(이전에는 스위치를 누르는 순간 기록이 지워져
  정작 재현 순간이 남지 않았다)

새로 만든다면 이 증상이 **새 구현에서도 나는지부터** 확인할 것. 같은
스택·같은 CSS 패턴이면 재현될 가능성이 높다.
