# 진단 정보 — 사용자가 겪은 것을 가져오는 길

> "아이패드 / 사파리에서 마드리드 선택 이후 다른 선택이 불가한 현상이
> 보이는데, 내 화면 로그를 갖고 갈 수는 없는거야? 내가 주거나"

가져올 수 없다. 아이패드 사파리는 **맥에 연결해 웹 인스펙터를 붙이지 않는
한 콘솔을 볼 방법이 없다.** 그러니 남은 길은 하나뿐이다 — 앱이 스스로
기록하고, 사용자가 그것을 꺼내 보낼 수 있게 하는 것.

## 무엇을 기록해야 쓸모가 있나

'버튼이 안 눌린다' 는 겉보기에 하나지만 실제로는 **전혀 다른 두 가지**다.

| | 무슨 일인가 | 고치는 곳 |
| --- | --- | --- |
| ① | 손가락이 그 버튼에 **닿지도 않는다** — 무언가가 위를 덮고 있다 | 레이아웃·CSS |
| ② | 닿기는 하는데 **아무 일도 일어나지 않는다** — 코드가 터졌거나 막혔다 | 자바스크립트 |

화면만 봐서는 구별되지 않는다. 그래서 두 가지를 나란히 남긴다.

- **눌림** — 캡처 단계에서 가로채, 누른 자리에 실제로 무엇이 있었는지
  (`document.elementFromPoint`). 버블링으로 들으면 위에 덮인 것이 이벤트를
  막았을 때 기록조차 남지 않는다 — 그게 정확히 알고 싶은 경우다.
- **동작** — 앱의 처리기가 실제로 돌았는지 (`mark()`).

정상이면 짝을 이룬다.

```
   0.2s 눌림 button.theme-head < div.theme-group "마드리드·중부 8곳 ▾"
   0.2s 동작 지역 펴기 center
   0.8s 눌림 img.city-photo < button.city-main < div.city-card
   0.8s 동작 도시 선택 madrid → 1곳
```

①이면 **눌림만 남고 동작이 따라오지 않으며**, 닿은 곳이 엉뚱한 것으로 찍힌다.
②면 눌림 뒤에 동작이 없고 대신 **오류** 줄이 남는다.

## 함께 담는 것

브라우저 문자열, 화면 크기·배율·터치 지원, 지금 실행 중인 판(`index-<해시>.js`)과
서버에 올라간 판, 서비스 워커와 캐시 이름, 저장분 크기. 어느 기기에서 어느
판으로 난 일인지 모르면 아무것도 좁힐 수 없다.

개인적인 것은 담지 않는다 — 누른 자리와 오류 문구, 브라우저 종류뿐이다.

## 어디서 꺼내나

화면 맨 아래 **`🛠 문제가 있나요 — 진단 정보 보내기`**. 펴면 내용이 보이고
`복사하기` / `파일로 받기` 가 있다. 사파리가 클립보드를 막으면 그렇게 적고
글상자를 길게 눌러 고르도록 안내한다.

고장 화면(`Crashguard`)에도 같은 것을 넣었다. 거기까지 갔다면 보낼 것이
있다는 뜻이다.

## 한계

- 자바스크립트 자체가 실행되지 않는 고장(번들 파싱 실패 등)은 기록도 남지
  않는다. 그때는 화면이 완전히 비고, 남는 단서는 '어느 판이 올라가 있나'
  뿐이다.
- 화면 전체를 덮는 것이 있으면 진단 패널도 누를 수 없다. 다만 지금 보고된
  증상은 일부만 안 되는 것이라 아래로 스크롤해 꺼낼 수 있다.

## 검증

`■ 8-b` 가 실제로 덮개를 만들어 눌러 보고, **눌림만 남고 동작이 따라오지
않는지**까지 본다. 기록이 두 경우를 갈라 주지 못하면 있으나 마나다.
총 144검사.

## 다시 고침 — 화면이 죽으면 진단을 누를 수가 없다

> "문제가 발생하면 내가 새로고침을 누르지 않고, 로그를 보낼 수 없는거야.
> 1. 화면이 잘리면서 멈추는 경우: 클릭 불가
> 2. 화면이 검정이 되는 경우: 클릭 불가"

맞는 지적이고, 이것 하나로 위의 설계가 통째로 쓸모없어진다. **정작 필요한
순간에 못 쓰는 계기는 계기가 아니다.** 사용자가 할 수 있는 것은 새로고침이나
탭을 닫고 다시 여는 것뿐인데, 그 사이에 기록이 사라지면 아무것도 오지 않는다.

세 가지를 고쳤다. 셋 중 하나만 빠져도 기록은 오지 않는다.

### ① 멈춘 순간을 앱이 스스로 적는다

누를 수 없는 상태를 사용자가 기록할 수는 없다. 감시자를 둘 둔다.

```
200ms 마다 도는 심장박동(setInterval) 이 1.5초 넘게 비었다
  → "자바스크립트가 N초 멈췄습니다 (메인 스레드 막힘)"

심장은 뛰는데 그리기(requestAnimationFrame) 가 3초 넘게 멈췄다
  → "그리기가 N초 멈췄습니다 (자바스크립트는 도는 중)"
```

**둘을 갈라 두는 것이 핵심이다.** 두 번째가 바로 '커서는 카드 위에 있는데
눌리지 않고 화면이 빈다' 의 모양이다 — 자바스크립트는 멀쩡히 도는데 합성기·
그리기 층만 죽은 상태. 지금까지 이 둘을 구별할 방법이 없었다.

페이지를 떠날 때도 한 줄 남긴다(`pagehide`/`beforeunload`, 한 번만).

### ② 기록이 앱보다 오래 산다

`sessionStorage` → **`localStorage`**. 세션 저장소는 탭을 닫으면 사라진다.
화면이 죽었을 때 사용자가 탭을 닫고 다시 여는 것은 가장 자연스러운 대응인데,
바로 그때 기록이 사라지면 안 된다.

### ③ 다시 열리면 앱이 먼저 말한다

아래쪽 진단 패널까지 내려가 펼치라고 하면 안 된다. 다시 열렸을 때 **본문 맨
위에** 뜬다.

```
직전에 화면이 멈춘 기록이 있습니다 (01:46:11)
멈춤 1건 · 오류 0건이 기록되어 있습니다.
[기록 복사하기]  [닫기]
```

누르면 바로 복사되고, 사파리가 클립보드를 막으면 글상자를 펴서 길게 눌러
고르도록 안내한다.

### 검증

`■ 8-c` 는 **메인 스레드를 실제로 3.5초 막고** 새로고침한 뒤 본다 —
안내가 먼저 뜨는가, 멈춘 것이 기록되었는가, 멈추기 직전에 무엇을 눌렀는지
남았는가, 새로고침으로 지워지지 않았는가. Chromium·WebKit 양쪽 167검사 통과.

```
✓ 멈춘 뒤 다시 열면 앱이 먼저 알린다 — 직전에 화면이 멈춘 기록이 있습니다
✓ 멈춘 것을 기록해 두었다 — 멈춤 자바스크립트가 3.7초 멈췄습니다 (메인 스레드 막힘)
✓ 멈추기 직전에 무엇을 눌렀는지 남아 있다 — 동작 도시 선택 madrid → 1곳
✓ 새로고침으로 기록이 지워지지 않는다 — 페이지 2번치
```
