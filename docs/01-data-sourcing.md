# 1. 데이터 출처 조사 · 비교 · 결정

여행 아이템 데이터를 어디서 가져올지 결정한 과정을 남긴다.
도시를 추가하거나 다른 나라로 확장할 때 이 판단을 다시 하지 않기 위한 문서다.

## 1.1 조사한 출처와 비교

| 출처 | 데이터 성격 | 저장(DB화) 가능 | 비용 | 판정 |
|---|---|---|---|---|
| Wikivoyage | 사람이 큐레이션한 볼거리·할거리·먹거리 목록 | 가능 (CC BY-SA 4.0, 출처표기 + 동일조건) | 무료, 키 불필요 | **채택 — 주력** |
| Wikidata | 좌표, 정식 명칭, 이미지, 언어판 수 | 가능 (CC0, 의무 없음) | 무료, 키 불필요 | **채택 — 정규화 축** |
| OpenStreetMap / Overpass | 카페·공원·전망대 등 누락분, 좌표 | 가능 (ODbL, 출처표기 + 동일조건) | 무료, 키 불필요 | **채택 — 보강** |
| Google Places API | 평점·리뷰·영업시간 (품질 최고) | **불가** | 유료 | **DB 소스로 탈락 → 런타임 링크로 전환** |
| YouTube · 여행 블로그 · SNS | 최신 트렌드, 현장감 | 불가 (ToS 위반, 스크래핑 차단) | — | 자동 수집 탈락, 수동 참고만 |
| 패키지 여행사 사이트 | 검증된 동선 | 불가 (저작권, robots 제한) | — | 동선 패턴 참고만 |
| 맛집 검색 앱 (망고플레이트 등) | 한국인 취향 맛집 | 불가 (공개 API 없음) | — | 탈락 |

## 1.2 결정을 가른 제약

Google Maps Platform 약관은 **Places 데이터의 사전 수집·저장을 금지**한다.
place_id 는 무기한 저장할 수 있고 좌표는 30일까지 캐시할 수 있지만, 이름·평점·리뷰·영업시간·사진은
요청할 때마다 실시간으로 받아 구글 귀속 표시와 함께 보여줘야 한다.

즉 "구글맵 후기를 미리 긁어 우리 DB를 만든다"는 경로는 애초에 성립하지 않는다.
2025년 3월부터 무료 한도도 SKU 별로 쪼개져(Essentials 10,000 / Pro 5,000 / Enterprise 1,000회),
Nearby Search 는 1,000회당 $32부터 시작한다.

## 1.3 결정 — 2계층 구조

이 제약을 우회하는 대신 역이용한다.

### A. 빌드 타임 — 저장이 허용된 것만 저장

```
Wikivoyage (아이템 후보 · 설명 · 요금 · 영업시간 텍스트)
  + Wikidata (좌표 · 정식명 · 언어판 수 = 유명도 지표)
  + OpenStreetMap (누락 보강)
        ↓  pipeline/collect.mjs (로컬에서 1회 실행)
        ↓  테마 분류 · 소요시간 추정 · 한국어 정제
        ↓
  app/public/data/cities/<slug>.json   ← 리포지토리에 커밋
```

유명도를 **Wikidata 언어판 수**로 계산한 것이 핵심이다.
40개 언어 위키백과에 실린 성당은 대표 명소이고, 2개 언어에만 있으면 숨은 곳이다.
상업 플랫폼의 평점을 쓰지 않고도 "유명한 곳 ↔ 숨은 곳" 축을 만들 수 있고, CC0 라 저장에 제약이 없다.

### B. 런타임 — 저장하지 않고 링크로 넘긴다

평점·영업시간·혼잡도·최근 사진은 **저장하지 않는다.**
각 아이템 카드의 `지도에서 보기` 버튼이 구글 지도를 열고, 사용자가 구글의 화면에서 직접 확인한다.

- 약관 위반 없음 (지도 앱을 여는 URL 에는 제한이 없다)
- API 키 없음, 서버 없음, 과금 없음
- 앱 자체는 오프라인에서도 동작한다

결과적으로 앱은 **키·서버·과금이 전혀 없는 순수 정적 PWA** 가 된다.

## 1.4 데이터 양 결정

산정 근거: 계획 3개 옵션 × 최대 5일 × 하루 4슬롯 = 60 아이템-슬롯.
옵션 간 중복을 50%로 보면 도시당 최소 40개의 고유 아이템이 필요하다.

| 기준 | 값 | 근거 |
|---|---|---|
| 도시당 최소 | 40개 (테마 5종 이상, 테마당 6개 이상) | 3개 옵션이 서로 달라 보이려면 필요한 최소량 |
| 도시당 목표 | 60~80개 | 5일 일정에서 선택의 여지가 생기는 구간 |
| 거점 도시 상한 | 70개 | 그 이상은 4단계 선택 피로가 급증 |
| 근교 도시 상한 | 40개 | 당일치기는 하루치면 충분 |
| 파일 크기 | 도시당 약 30~60KB | 모바일에서 도시 단위로 지연 로딩 |

근교 도시는 하루만 머무르므로 40개면 충분하고, 거점 도시는 3~4일을 채워야 하므로 70개를 상한으로 둔다.

## 1.5 필수 필드

| 필드 | 출처 | 용도 |
|---|---|---|
| `id`, `name`, `nameEn`, `nameLocal` | Wikivoyage | 표시, 지도 검색어 |
| `theme` | 규칙 기반 분류 | 3단계 테마 묶기 |
| `desc` | Wikivoyage 요약 | 4단계 선택 판단 |
| `lat`, `lon` | Wikivoyage / Wikidata | 5단계 동선 최적화, 길찾기 |
| `durationMin` | 테마 + 본문 추정 | 5단계 시간표 |
| `priceEur` | Wikivoyage 요금 파싱 | 예산 필터, 비용 합계 |
| `popularity` (1~5) | Wikidata 언어판 수 | 유명한 곳 ↔ 숨은 곳 축 |
| `energy` (1~5) | 본문 키워드 | 체력·동행자 보정 |
| `bestSlots` | 테마 규칙 | 시간대 배치 |
| `tags` | 본문 키워드 | 음식 취향 매칭 |
| `attribution` | 고정 | 라이선스 표기 의무 |

## 1.6 라이선스 이행

- Wikivoyage: CC BY-SA 4.0 — 앱 하단과 각 아이템에 출처 표기, 데이터셋도 동일 조건으로 공개
- Wikidata: CC0 — 의무 없음
- OpenStreetMap: ODbL — `© OpenStreetMap contributors` 표기
- Google: 저장하지 않으므로 귀속 의무 발생 지점이 없다 (링크만 제공)
