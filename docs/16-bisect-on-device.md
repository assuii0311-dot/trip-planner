# 기기에서 원인 좁히기 — 추측 대신 이분 탐색

## 지금까지 무엇이 있었나

아이패드 사파리에서 세 가지가 보고됐다.

1. 첫 화면이 오래 걸리거나 뜨지 않는다
2. 갑자기 멈췄다가 검은 화면이 된다
3. **마드리드가 있는 칸에서 톨레도를 누르면** 그 뒤로 다른 도시가 눌리지
   않는다 (커서는 카드 위에 있는데 반응이 없다)

세 번 고쳤고 세 번 다 빗나갔다. 고친 것들이 그 자체로 잘못이었던 것은
맞다 — 낡은 캐시, `height: 100%`, 붙박이 막대의 흐림 합성, 그리고 애초에
그 수정들이 기기에 닿지 않던 문제까지. 하지만 **증상은 남았다.**

## 왜 못 찾았나

문제를 볼 수 있는 기계가 하나뿐이기 때문이다.

사파리 엔진(WebKit)을 이 환경에 올려 아이패드 크기·다크 모드·터치로 같은
흐름을 돌려 봤다. 사용자가 말한 조건 그대로 — 목록을 스크롤한 상태에서
마드리드가 있는 칸의 톨레도를 누른다.

```
톨레도 누른 뒤: 카드 8 · 문서 4055px · 스크롤 900/1194
   위치/높이 마드리드:56/278 톨레도:344/278 세고비아:633/277 아빌라:920/277
             쿠엥카:1206/277 살라망카:1493/277 알칼라데:1780/277 아랑후에:2067/277
   사진 ok560 × 8
선택된 카드 2곳 · 오류 없음
```

**DOM 은 완벽하다.** 카드 여덟 장이 다 있고, 높이도 정상이고, 사진도 다
로드됐고, 오류도 없다. 헤드리스 WebKit 은 실기기의 GPU 타일링·합성기까지
흉내 내지 못하고, '비어 보인다'·'눌리지 않는다' 는 정확히 그 층의 증상이다.

즉 **이 문제를 볼 수 있는 기계는 그 아이패드뿐이다.** 여기서 아무리 오래
봐도 나오지 않는다.

## 그래서 방법을 바꾼다

추측 → 배포 → 물어보기를 반복하면 한 바퀴에 하루가 간다. 대신 **한 번에
한 가지씩 끄고 그 기기에서 확인**한다. 이분 탐색이다.

```
?safe=1              의심되는 것 전부 끈다
?off=photos          도시 사진만 끈다
?off=sticky,fixed    여러 개를 함께 끈다
```

끌 수 있는 것과, 그것이 용의자인 이유:

| 스위치 | 끄는 것 | 왜 용의자인가 |
| --- | --- | --- |
| `photos` | 도시 사진 | 카드마다 이미지. 합성 레이어와 디코딩 비용 |
| `sticky` | 머리줄 고정 | `position: sticky` 는 합성 레이어를 만든다 |
| `fixed` | 바닥 막대 고정 | `position: fixed` 도 마찬가지 |
| `shadow` | 그림자·둥근 모서리 | `overflow:hidden` + `border-radius` + `box-shadow` = 클립 레이어 |
| `preview` | 1단계 미리보기 | 도시를 고르면 아래에 새로 붙는 부분 |

주소를 손으로 칠 필요는 없다. 화면 맨 아래 진단 패널에 **눌러서 옮겨가는
단추**로 넣었다. 지금 무엇이 꺼져 있는지는 화면 위쪽 띠에 표시되고,
**진단 기록에도 함께 남는다** — 어떤 조합에서 무슨 일이 났는지 나중에도
맞대어 볼 수 있어야 하기 때문이다.

## 읽는 법

- **`?safe=1` 로 증상이 사라진다** → 범인은 저 다섯 안에 있다. 하나씩
  되돌려 가며 어느 것에서 다시 나는지 본다. 두세 번이면 끝난다.
- **`?safe=1` 로도 증상이 남는다** → CSS 합성 문제가 아니다. 리액트 렌더링
  이나 사파리 자체 쪽이고, 그때는 진단 기록의 `눌림`/`동작` 짝을 본다.

어느 쪽이든 다음 한 걸음이 정해진다. 그게 이 도구의 전부다.

## 검증

`■ 9-b` 가 본다 — 평소에는 스위치가 걸리지 않는지, 사진만 끌 수 있는지,
끈 것을 화면에 알리는지, **전부 끈 채로도 도시를 고르고 다음 단계까지
가는지**(못 가면 좁히는 데 쓸 수가 없다), 진단에 조합이 남는지, 화면에서
눌러 옮겨갈 수 있는지. Chromium·WebKit 양쪽 160검사 전부 통과.
