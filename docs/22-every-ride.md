# 타는 것은 모두 안내한다

보고된 두 가지다.

1. 근교 왕복 안내가 도시 간 이동과 다른 모양이고 내용이 모자랐다.
2. 마요르카 → 지로나 구간의 안내가 아예 없었다.

원인은 서로 달랐지만, 고치고 나니 규칙은 하나로 모였다 —
**그날 실제로 타는 것은 모두, 같은 모양으로 적는다.**

## 1. 근교 왕복이 반의 반만 적혔다

| | 짐 옮기는 이동 | 근교 왕복 (예전) |
|---|---|---|
| 무엇을 타는가 | ✅ | ✅ |
| 몇 시에 나서는가 | ✅ | ❌ |
| 몇 시에 닿는가 | ✅ | ❌ |
| 몇 시에 돌아오는가 | — | ❌ |
| 요금 | ✅ | ❌ |
| 환승·대기 | ✅ | ❌ |
| 다른 수단 | ✅ | ❌ |
| 시간표 출처 | ✅ | ❌ |

근교에 있던 것은 하루 머리줄의 한 줄이 전부였다.

```
🚄 고속열차 편도 1시간 28분 · 왕복
```

실제로 타는 시간은 근교 쪽이 더 긴 날도 있다. 톨레도 왕복 2시간 38분,
아빌라 왕복 3시간 24분이다. 짐을 옮기느냐 아니냐가 다를 뿐, 사람이 알아야
할 것은 같다.

## 2. 하루에 두 번 옮기는 날은 앞 구간이 사라졌다

`PackedDay.move` 가 **하나**였다.

```ts
cur.move = leg;   // ← 덮어쓴다
```

아침에 팔마→지로나로 들어와, 지로나를 보고, 저녁에 지로나→바르셀로나로
다시 옮기는 날. 뒤엣것이 앞엣것을 덮어써 **팔마→지로나가 화면에서 통째로
사라졌다**. 여정 요약에는 있고 상세 일정에만 없으니, 섬에서 어떻게 나오는지
알 방법이 없었다.

하루가 한 번만 옮긴다는 법이 없다 — 하루에 도시가 둘 이상 들어갈 수 있게
만든 것이 새 날 모델인데, 이동은 하나만 담고 있었다. 새 모델을 만들면서
같이 고쳤어야 할 것을 빠뜨린 자리다.

## 고친 방법

- `PackedDay.move` → **`moves[]`**. 그날 옮긴 구간을 모두 담는다.
- `PlanDay.travel` → **`travels[]`**. 짐 옮기는 이동과 근교 왕복이 함께
  들어간다. 지도(`TripMap`)도 이동을 모두 그린다.
- `TravelBlock` 하나가 둘 다 그린다. 근교면 경로를 `마드리드 → 톨레도 →
  마드리드 (왕복)` 로 적고, 가는 편과 오는 편 시각을 함께 쓰고, 요금은
  왕복으로 적고, 이동 시점(`언제 옮길까요`)은 묻지 않는다 — 짐을 안 옮기니
  고를 것이 없다. 테두리를 점선으로 눕혀 '여기서 자지는 않는다' 를 보인다.
- **오는 편 시각**은 그날 일정이 정한다. 저녁을 먹으러 거점으로 돌아오는
  자리에서 역산해 채운다. 계획안(빡빡·보통·느긋)마다 다르므로 안마다 따로.
- 근교 왕복도 **고른 수단과 요일**을 따른다. 예전에는 언제나 가장 빠른 편으로
  셌기 때문에, 수단을 바꿔도 왕복 시간이 그대로였다.
- 근교 날은 **실제로 닿는 시각**부터 시작한다. 예전에는 '하루 시작 + 75분'
  이라는 어림수였다. 이제 09:48 에 닿는다고 적으므로, 09:15 부터 일정을 넣으면
  그 자리에서 어긋난 것이 보인다.

머리에 크게 쓰는 숫자도 고쳤다. 처음에는 근교에 '나선 시각 ~ 돌아온 시각'
을 썼는데, 그건 톨레도에서 논 시간까지 더한 **11시간 24분**이었다. 바로 옆
이동 블록의 3시간 25분은 순수 이동 시간이라, 같은 자리의 같은 크기 숫자가
다른 뜻이었다. 지금은 둘 다 **타는 시간**이고, 나가 있는 시간은 작게 따로 쓴다.

지나는 길에 조사 하나도 고쳤다 — "세비야을 길게 씁니다" → "세비야를".

## 다시 안 나게

**엔진** (`planner-check.mjs`) — 84가지 조합(7묶음 × 3가지 일수 × 2가지 숙박
배치 × 2가지 도착시각)에 약속을 건다.

1. 실제로 타는 이동이 모두 안내된다 (날이 모자라 잘려 나간 도시로 가는
   구간은 애초에 타지 않으므로 뺀다 — '날 부족' 을 '안내 없음' 으로 잘못
   읽지 않기 위해서다)
2. 근교가 모두 안내된다
3. 안내가 같은 것을 담는다 (수단·시각·대안이 다 있는가)
4. 근교에 오는 편이 적힌다
5. 근교에 닿기 전 시각에 일정이 잡히지 않는다

**화면** (`verify.mjs ■12`) — 근교 날에 같은 블록이 실제로 그려지는가,
그 안에 왕복 표시·가는 편·오는 편·요금·다른 수단이 있는가, 짐을 두고
간다고 알리는가, 이동 시점은 묻지 않는가, 예전 한 줄짜리 배지가 사라졌는가.

두 고침을 하나씩 되돌려 각각 걸리는 것을 확인했다.

| 되돌린 것 | 걸린 검사 | 나온 말 |
|---|---|---|
| 이동을 하나만 담기 | 타는 구간이 모두 안내된다 | 12가지 — 코르도바→마드리드 |
| 근교 안내 빼기 | 근교도 빠짐없이 안내한다 | 론다, 네르하, 코르도바, 톨레도, 세고비아, 아빌라, 몬세라트 |
