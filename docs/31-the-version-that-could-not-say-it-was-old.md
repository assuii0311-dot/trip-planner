# 스스로 낡았다고 말하지 못한 판

> 사용자 보고: *"지금은 아이패드이고, 폰과 패드 모두 확인해봤는데, 전혀
> 새로 추가한 기능이 보이지 않아."*

네 가지를 새로 넣고 배포한 직후였다. 4단계 구글 지도 저장, 30분 눈금,
3단계 고민 중, 기기 사이로 옮기기. 두 기기 모두에서 **하나도** 보이지
않는다고 했다.

---

## 서버는 멀쩡했다

먼저 의심할 곳을 하나씩 지웠다.

| 의심 | 확인한 것 | 결과 |
|---|---|---|
| 배포가 안 나갔다 | `trip/main` 에 마지막 작업 커밋이 들어 있는가 | 들어 있다 |
| 빌드가 낡았다 | 맨 바닥에서 다시 빌드해 실행판과 바이트 비교 | 서비스워커 `?v=` 말고는 같다 |
| 번들에 기능이 없다 | 실행 중인 `main-*.js` 를 받아 문자열 검색 | 넷 다 있다 |
| 예전 저장분이 깨뜨린다 | 옛 형식(`dayStart: 'normal'`)을 넣고 4단계까지 | 옮겨지고 다 보인다 |
| 낡은 판 알림이 고장 | 판 둘을 만들어 갈아 끼우고 알림을 봤다 | **뜬다** |

전부 정상이었다. 그런데 기기에서는 보이지 않는다.

## 알림은 뜬다 — 지금 판에서만

마지막 줄이 함정이었다. *지금 판* 에서 알림이 뜨는지를 봤을 뿐이다.
문제는 기기가 들고 있는 것이 **지금 판이 아니라는** 데 있었다.

낡은 판 확인은 이렇게 돈다.

1. 지금 문서가 부르는 진입 스크립트 이름을 읽는다
2. 서버에 같은 주소를 캐시 없이 다시 물어 그 이름을 읽는다
3. 다르면 "새 판이 나와 있습니다" 를 띄운다

나라를 쪼개기 전(`219aaeb`, 9월 3일) 판의 2번은 이랬다.

```js
return (html.match(/index-[A-Za-z0-9_-]+\.js/) ?? [null])[0];
```

이름이 **박혀 있었다.** 나라를 쪼개면서 Vite 가 번들을 나눴고 이름이
`main-*.js` · `landing-*.js` 로 바뀌었다. 그 뒤로 어떤 배포도
`index-*.js` 를 내놓지 않는다.

그러니 찾지 못한다 → `null` → "확인할 수 없다" → **조용히 아무 말 없음.**

그리고 아이패드 사파리는 탭을 그대로 되살린다. 앱을 다시 열어도 새로
받아오는 항해가 일어나지 않는다. 알림이 유일한 탈출구였는데 그 알림이
스스로 꺼져 있었다. 낡은 판은 자기가 낡았다는 것을 **영영 말할 수 없다.**

두 기기가 동시에 그런 것도 이것으로 설명된다. 둘 다 9월 3일 이전
어느 날의 탭을 들고 있었다.

## 검사는 왜 못 잡았나

검사가 있기는 했다. 그런데 두 겹으로 죽어 있었다.

```js
const docPath = process.env.VERIFY_DOC ?? null;   // 아무도 주지 않는다
...
if (docPath) {                                     // 그래서 통째로 건너뛴다
  await writeFile(docPath, original.replace(/index-[A-Za-z0-9_-]+\.js/, ...));
}                                                  // 줬어도 이 replace 는 무일
```

`VERIFY_DOC` 을 주는 사람이 없으니 이 세 검사는 **한 번도 돌지 않았다.**
검사 자신도 `index-` 를 박아 두고 있었으므로, 설령 줬더라도 아무것도
바꾸지 못하는 글자였다. 223건이 통과한다는 말에 이 셋은 애초에 없었다.

안 도는 검사는 검사가 아니다.

## 무엇을 고쳤나

**① 이름을 못 읽으면 '모르겠다' 가 아니라 '바뀌었다' 로 읽는다.**

우리 페이지인데 진입 스크립트를 하나도 못 뽑았다면, 그건 판의 모양이
바뀌었다는 뜻이다. 여기서 잠자코 있는 것이 바로 이 고장이었다.

```ts
const theirs = joinNames(entrySrcs(html));
if (!theirs) return '(이름을 읽지 못한 새 판)';
```

**② 대신 '우리 페이지인가' 를 먼저 묻는다.**

호텔·공항 와이파이의 로그인 페이지도 200 으로 온다. 그것까지 새 판으로
치면, 망 없는 곳에서 쓰라고 만든 앱이 하필 거기서 거짓말을 한다.
`id="root"` — 앱이 스스로 붙는 자리 — 가 있는 글만 본다.

**③ 검사를 파일 대신 가로채기로 돌린다.**

`VERIFY_DOC` 을 없앴다. Playwright 로 `?v=` 붙은 물음만 가로채 원하는
글을 내준다. 준비물이 없으니 늘 돈다. 네 가지를 본다.

| | 내주는 글 | 기대 |
|---|---|---|
| 평소 | 진짜 그대로 | 알림 없음 |
| 로그인 페이지 | `id="root"` 없는 글 | 알림 없음 |
| 새 배포 | 이름을 바꾼 글 | 알림 뜸 |
| **모양이 바뀜** | module 스크립트를 지운 글 | **알림 뜸** |

## 남는 것

고친 것은 **다음번** 을 막는다. 이미 낡은 판을 들고 있는 기기는 이 고침이
닿지 않는 곳에 있다 — 고침을 받으려면 새로 받아야 하고, 새로 받으라고
말해 줄 수 있는 것이 바로 그 고침이기 때문이다.

그 기기는 사람이 한 번 끊어 줘야 한다. 주소를 새로 열거나(되살린 탭이
아니라), 사파리 설정에서 이 사이트 데이터를 지우면 된다.

> 이름을 박아 넣는 것은 그 자리에서는 늘 맞다. 틀리는 것은 나중이고,
> 틀릴 때 조용하다.
