# 5. 아이템 설명 형식

> [정의] 아이템의 설명이 부족하여 여행자가 판단하기 어려움
> [요청] 아이템 설명 형식에 대한 합의 필요

## 5.1 왜 바꿨나

이전 형식은 `desc` 한 줄이었다. "가우디가 40년을 매달렸고 아직 짓고 있는 성당" 같은
문장은 그 장소가 무엇인지는 알려 주지만, 여행자가 실제로 해야 하는 판단에는 답하지 못한다.

- **가야 하나?** — 나에게 값어치가 있는 곳인가
- **어떻게 가나?** — 예약이 필요한가, 오늘 문을 여는가, 얼마나 걸리는가
- **뭘 조심하나?** — 갔다가 못 들어가는 일이 없으려면

한 줄로는 이 셋을 동시에 못 한다. 그렇다고 한 줄을 다섯 줄로 늘리면 목록을 훑을 수 없다.
그래서 **목록에서 보이는 것과 펼쳤을 때 보이는 것을 나눴다.**

## 5.2 네 부분

```
summary    목록용 한 줄, 40자 안팎
           "아직 짓고 있는 가우디의 성당. 오후 빛이 절정"

why        왜 가는가, 1~2문장
           "가우디가 40년을 매달렸고 100년 넘게 아직 짓고 있는 성당입니다.
            안에 들어가면 기둥이 나무처럼 갈라져 천장을 받치고, 오후에 서쪽
            스테인드글라스를 통과한 빛이 기둥 숲을 붉게 물들입니다."

practical  예약 · 휴관 · 붐빔 · 소요 · 요금 · 영업시간
           예약: 시간 지정 입장. 성수기에는 며칠 전에 매진됩니다
           소요: 약 1시간 30분
           요금: €22

caution    주의점, 있을 때만
           "탑에 오르는 표는 따로이고 수량이 적습니다. 어깨와 무릎을 가리는
            옷차림이 필요합니다."
```

3단계 목록에서는 `summary` 한 줄과 태그만 보이고, '자세히'를 누르면 나머지가 열린다.
6단계 가이드에서는 항목을 펼치면 같은 블록이 길찾기 링크와 함께 나온다.
5단계 계획표에서는 `summary` 와, 예약이 필요하거나 주의점이 있는 경우 그 한 줄만 강조한다.

## 5.3 실무 정보는 지어내지 않는다

이것이 이 형식의 핵심 규칙이다.

| 항목 | 어디서 오나 |
|---|---|
| 소요 | `durationMin` 에서 계산 (`약 1시간 30분`) |
| 요금 | `priceEur` 에서 계산 (`€22` / `무료` / `정보 없음`) |
| 휴관 | 영업시간 문자열에서 역산 (`Tu-Su 09:30-20:00` → 월요일 휴무) |
| 영업시간 | 원문 그대로 |
| 예약 | 출처가 말해 준 경우에만 사람이 적는다 |
| 붐빔 | 출처가 말해 준 경우에만 사람이 적는다 |
| 주의점 | 출처가 말해 준 경우에만 사람이 적는다 |

휴관일 역산은 **주 4일 이상 닫는 것으로 읽히면 표기가 불완전한 것으로 보고 비운다.**
Wikivoyage 영업시간 문자열은 계절별로 여러 구간을 이어 붙인 것이 많아, 일부 요일만 적힌
문자열을 그대로 믿으면 열려 있는 날을 휴관으로 만들어 버린다.

예약 여부와 붐비는 시간은 계산할 수 없다. 비어 있는 편이 그럴듯하게 틀린 것보다 낫다는
기준으로, **모르면 비운다.** 그래서 `practical.booking` 이 있는 아이템은 전체의 일부다.

### 이 규칙을 세우고 나서 발견한 것

설명을 다시 쓰면서 마드리드 왕궁이 '무료'로, 5유로짜리 보카디요가 '€1011'로 표시되는 것을
발견했다. 가격 파서가 (1) 문자열 어딘가에 `free` 가 있으면 무조건 0으로 읽고,
(2) 문자열의 모든 숫자를 평균 내고 있었다. 미술관 대부분이 '폐관 2시간 전 무료' 같은 문구를
함께 적어 두어 254개 아이템이 유료인데 무료로 표시됐고, 연도(2017)가 평균에 섞여 들어가
세 자리 값이 나왔다.

통화 기호가 붙은 첫 금액만 읽도록 고쳤다. 무료 254 → 161개.

## 5.4 작업 방식

설명은 도시별 JSON에 사람이 직접 쓴다. 파이프라인은 이 파일을 최종 목록에 한 번 접어 넣는다.

```bash
node pipeline/dump.mjs granada            # 원문·기존 한국어와 함께 목록 확인
# pipeline/ko-patch/granada.json 에 summary/why/booking/busy/caution 작성
node pipeline/merge-ko.mjs granada        # pipeline/ko/spain/granada.json 에 병합
node pipeline/coverage.mjs                # 진행률
```

`merge-ko.mjs` 는 `name`, `theme`, `durationMin`, `energy`, `bestSlots` 같은 기존 보정값을
건드리지 않고 설명만 갈아 끼운다.

## 5.5 결과

60개 도시 2,137개 아이템 전부를 새 형식으로 다시 썼다. `coverage.mjs` 기준 100%.

작업 중 자동 판정이 못 잡은 중복 아이템 24건을 찾아 `DROP_IDS` 로 지웠다
(같은 장소가 Wikivoyage 리스팅과 Wikidata 보강에서 각각 들어온 경우 —
'오르가스 백작의 매장'과 '산토 토메 성당', '레알 마드리드'와 '베르나베우' 같은 것들).
자동 규칙을 넓히면 '말라가 대성당'과 '말라가 박물관'까지 합쳐 버려서, 전수 점검에서
나온 것만 이름으로 지웠다.
